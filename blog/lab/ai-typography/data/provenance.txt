- `frontend-design`. I deliberately did not follow its advice to pick a distinctive typeface: Chinese web fonts run to several MB, and an in-app page should load instantly and look like the system, so the page uses system fonts.
**Files read**
- `blog/public/lab/ai-typography/prompt.txt`. It is the same brief as yours, except the output file is named `release1.html`.
- The six posts in `blog/src/content/posts/*.mdx`, searched with `rg` rather than read in full, to see how the blog spaces Chinese against English and digits. There were 0 cases of Chinese written directly against Latin letters or digits, and dates appear as "2026 年 8 月".
- **Wording is unchanged; only spacing was added.**
  - I put a space between Chinese and English or digits, following the blog's own convention, e.g. "用 Claude Code 上传" and "2026 年 10 月 28 日".
  - I also put a space between numbers and units ("2 GB", "86.4 MB"). The blog gives no guidance on this; it's my choice, based on the national standard and common Chinese copy-style guides, and easy to revert.
- **Quotes and dashes.** Measured in Chrome on macOS, PingFang's default “” are only 0.54em wide (half-width). I added a font rule that sends only these punctuation characters to a Chinese font with the full-width glyph switched on. The quotes now measure 1em, and the two dashes in "——" join into one line. Where two quotes sit next to each other (“1 天”“7 天”), I narrowed the first one (0.44em) so the pair doesn't leave a two-character gap.
- **Things kept from breaking across lines.** "iOS 18", "iOS 15", "2 GB" and "86.4 MB" use non-breaking spaces; "Wi-Fi" and 《报告-2026Q3》 are wrapped so they don't split.
**Checks before delivery** (Chrome driven by `playwright-core`; the scripts are in the session scratchpad)
- **Not checked: iOS / Safari.** There is no WebKit browser in this environment. Three iOS simulators were running, but other sessions may be using them, so I left them alone. If Safari ignores the punctuation font rule, the quotes just fall back to the default half-width glyphs, so nothing breaks.

## 排版上做了什么（交付时改动了你给的文案写法）
- **中文和英文、数字之间加了空格**，比如「用 Claude Code 上传」「超过 2 GB」「2026 年 10 月 28 日 · 86.4 MB」。「35%」不加；挨着全角标点的地方也不加。依据是你提示词里自己的写法（「App 图标」「用 HTML + CSS」）和 autocorrect hook。
- **引号和破折号保留你的写法**（“” 和 ——），但用 `unicode-range` 把这几个字符指定给苹方。实测在 15px 下，引号从 6.7px 变成 8.1px，破折号从 13px 变成 15px。不这样做的话，SF 会把引号画成像英寸符号一样的细斜线。
  - 中途我删过一次这段字体设置，因为一个单独搭的测试页里看不出区别。换到真实页面里对比后发现确实有用，又加了回来。
- 行高 1.6～1.7，加了 `text-wrap: pretty`。
**没验证到**：iOS WebKit / 真机（本机 Playwright 只有 Chromium），包括苹方字体指定在 iOS 上是否生效；读屏软件的实际播报；Android 和 Windows 的字体效果。
