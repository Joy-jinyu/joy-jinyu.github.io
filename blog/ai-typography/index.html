排版：标点都照顾到了，层级只靠字号

上下两级要在字号以外再分开一处，接口文案的空格交给 CSS，全角引号挨着要处理；附一段贴进 DevTools 的字号表脚本。

发布 2026.11.18更新 2026.11.18阅读约 11 分钟

下面是 AI 写的「版本更新」页。左边是页面本身，右边是从页面上量出来的各层级样式。点「拿掉字号」，页面里所有文字会改成同一个字号，只剩字重和颜色，看还剩几级。

  1. 导语这次更新重做了文件上传。
  2. 分组标题新功能
  3. 条目标题断点续传
  4. 条目说明上传中断后，重新连上 Wi-Fi…
  5. 列表条目深色模式下，图片缩略图不再发灰。

    左边是真页面，右边是从它身上量出来的样式。「拿掉」一个通道，就是把页面里所有文字的这一项改成同一个值，看剩下的还能不能把层级分开。

    第 2、3 份里，「新功能」是分组标题，「断点续传」是它下面的条目标题。两者都是 600 的字重、同一种黑，只差 2px：一个 18，一个 16。字号一拿掉，两级就并成了一级。改过的版本里，分组标题是 13px 的灰色小字，加了字距；拿掉字号以后，它还是灰色、还隔着字距，和条目标题分得开。

    中文排版的细节，三份反倒都做得很好：汉字和英文、数字之间加了空格，「Wi-Fi」「2 GB」不让折行，引号和破折号交给了苹方。这些现在的模型已经会了，不用再写进规则。这篇讲它们没做到的三件事：层级为什么只靠字号分不开；文案来自接口时，空格该交给谁；用全角引号时，挨在一起的两个怎么办。最后给一段能列出任何页面字号表的脚本。

    范围：三个全新的 Claude Code subagent 各写一次，2026-10-31；在 macOS 的 Chrome 156 里量（深色数据、空格和引号宽度是 2026-11-18 在 Chrome 157 里补测的），375px 宽的手机视口，没有在 Safari、Windows、Android 和真机上量过。prompt 和原始数据在附录。

    档多不是问题

    字号分几档不要紧，要紧的是页面上的上下两级靠什么分开。三份页面的文字各用了 6–7 种字号，13 到 18 之间几乎每个整数都用上了，看上去很乱；可 Apple 的 iOS 默认字号表也有 10 档，17、16、15、13、12、11，相邻两档只差 1–2 个点。

    这里要分清两件事：刻度上相邻的两档，和页面上的上下两级。iOS 的 Callout 16 和 Subhead 15 只差 1 个点，它们是刻度上的邻居，各管各的用处。iOS 字号表里同样大小的两档，靠的是别的通道：Headline 和 Body 都是 17 点，一个半粗、一个常规。刻度上挨得近不要紧，要紧的是上下两级之间，除了字号还有没有别的不同。

    两级之间要有字号以外的不同

    上下两级之间，要有字号以外的不同。开头的演示把所有文字改成同一个字号：还靠字重、颜色、字距分开的两级，仍然分得开；只靠字号的，就并成了一级。我们的解释是，字号的差别要放在一起比才看得出来，字重、颜色、字距是每段文字自己带着的，单独看一段也认得出属于哪一级；这个解释没有找到实验出处。留白和位置也要靠比较，所以下面说的「通道」只算字重、颜色、字距。

    分组标题和条目标题偏偏很少紧挨着。「新功能」下面先是「断点续传」，再是一段说明，再是「链接有效期」。读者看到「链接有效期」时，要拿它和几行之上的「新功能」比，18 和 16 之间那 2px 比不出来，两级就看成了一级。三份页面在这一对上都只用了字号：

    pretty 只治一个字的孤行

    三份页面的段落都加了 text-wrap: pretty，它能做的比看上去少。我们把同样七段话，宽度从 300 到 430px 每 1px 排一次：最后一行只剩一个字的情况，wrap 下有 115 次，pretty 下是 0 次。但它只是把一个字变成两个字：最后一行只剩一两个字的总次数没变，都是 175 次，占 19.1%（输出）。Chrome 的说明也写着，pretty 目前「only handles orphans」。

    所以加上它没坏处，但别指望它管住段尾。真正在意的短段落，比如提示框、按钮下的小字，要在最窄和最宽的视口下各看一次最后一行。

    文案来自接口时，空格交给 CSS

    空格写死在文案里，文案一换就没了；文案来自接口或运营后台时，空格要交给 CSS。三份页面的空格都是写进文案里的，这个静态页面没问题，接到接口上就不行了。

    CSS 有专门做这件事的属性 text-autospace：在汉字和西文、数字之间自动加一点空白，不改文案。按 MDN，它 2025 年 11 月成为 Baseline，Chrome 140、Safari 18.4、Firefox 145 起支持。要注意的是，浏览器默认不开。 规范里它的初始值是 normal，会加；但 MDN 的兼容数据注明，三家浏览器目前的默认值都是 no-autospace（见 CSSWG 的 issue #12386）。三份 AI 页面都没有打开它。要用就自己写一行：

    接口原文

    用Claude Code上传的大文件（超过2GB）会自动分片

    手敲空格

    用 Claude Code 上传的大文件（超过 2 GB）会自动分片

    原文 + text-autospace

    用Claude Code上传的大文件（超过2GB）会自动分片

    你的浏览器还不支持 text-autospace，第三行和第一行会一模一样。Chrome 140、Safari 18.4、Firefox 145 起支持。

    在你的浏览器里实时排的。标出的是汉字和西文、数字之间多出来的空白，读数是每一处多出多少，单位是字号（em）。

    它加的空白比手敲的空格窄：规范定的是 1/8 个汉字宽，手敲的空格落在英文系统字体上，正文字号下约 1/4 个字宽（输出）。W3C 的中文排版需求（clreq）建议汉字和西文之间「up to 1/4 em」，两种都在范围里，看上去一个紧一点、一个松一点。

    两者可以一起用。文案里已经有空格的地方，text-autospace 不会再加：我们量过，手敲空格再打开它，空隙和只敲空格时一样（输出）。所以稳妥的做法是 CSS 里打开 text-autospace: normal，接口来的文案照原样显示；手写的静态文案照常加空格。不支持的浏览器里，接口来的原文还是挨着的，至少内容没被改动。

    引号“
    –
    两个“——”
    –
    ”和“挨着

    在你的浏览器里实时排的，宽度单位是字号（em）。你的系统里没有苹方时，后两种会落到别的字体上，以读数为准。

    用全角引号，就要把「两个引号挨在一起」当成一种要处理的情况。先说背景：字体栈把英文系统字体放在前面时，引号和破折号会用上英文字体的字形：引号只有 0.44em 宽（15px 正文；字号越大越窄，40px 时 0.37em，输出），细得像英寸符号；两个破折号并排时中间断开。三份 AI 页面都处理了，办法一样：用 @font-face 加 unicode-range 定义一个只覆盖这几个字符的字体，排在字体栈第一位，指向本机的苹方。这一条现在的模型也已经会了。

    值得说的是第 3 份多走的一步：它打开了 fwid，取全角字形，每个引号占一个字宽，clreq 也写着标点「usually occupy 1 em」。全角引号的麻烦在挨在一起的时候。「“1 天”“7 天”」里，前一个的后引号和后一个的前引号各占一个字宽，中间空出将近一个字。

    Chrome 默认的 text-spacing-trim 会把相邻的全角标点挤紧，比如「）。」从 2em 挤成 1.5em。可对这种用 fwid 换出来的全角引号，它不起作用：挨着的两个仍然各是 1em（输出）。规范把弯引号列进了要挤的全角标点（「Also includes LEFT SINGLE QUOTATION MARK (U+2018) and LEFT DOUBLE QUOTATION MARK (U+201C).」），但也留了口子：字体没法区分全角和半角字形时，浏览器不能加减空隙。Chrome 判断引号是不是全角，看的是字体默认的字形；Chromium 的源码注释写着，用 fwid 切到全角字形是 Adobe 的约定，「The current logic doesn’t support this convention」。第 3 份只好手动把前一个引号包进 <span>，换回英文系统字体的窄引号：

    右下角会出现一个面板：上面是「容易看成同一级」的样式对，中间是三项中文排版检查，下面是全部样式，点一行就在页面上框出用它的文字。

    它做三件事：

    1. 列出页面上每一种文字样式，按字号排好，点一行就在页面上框出用它的文字。字号的计数包括提示框里的「!」图标，所以第 2、3 份和改过的版本会比正文里说的多一种。
    2. 挑出「在页面上离得近、只差一个通道、而且差得不多」的样式对。离得近，指左右有重叠、上下间隔不超过两个字号；差得不多，指字号差 2px 以内、字重差 100 以内，或者两种颜色几乎一样。这几个阈值是经验值，不是哪份规范规定的。只看离得近的，是为了把比较限定在同一块内容里；分组标题和它下面紧贴着的第一条条目标题，正好落在这个范围里。
    3. 查三件中文排版的事：<html lang>、text-autospace 开没开、正文字体排出来的引号是不是英文字体的窄引号。

    在第 2、3 份上，它都只挑出 1 对：「新功能」和「断点续传」，只差字号 18 和 16。第 1 份的分组标题是 20px，差了 4px，超出阈值，没被挑出来，可它同样只靠字号区分。改过的版本上是 0 对。四份页面都没开 text-autospace（输出）。脚本挑出来的要逐个看；第 1 份这种差得多一点的，还要靠上一节那行「拿掉字号」。
