下面是 AI 写的「版本更新」页。左边是页面本身，右边是从页面上量出来的各层级样式。点「拿掉字号」，页面里所有文字会改成同一个字号，只剩字重和颜色，看还剩几级。

<TypeLevels />

第 2、3 份里，「新功能」是分组标题，「断点续传」是它下面的条目标题。两者都是 600 的字重、同一种黑，只差 2px：一个 18，一个 16。字号一拿掉，两级就并成了一级。改过的版本里，分组标题是 13px 的灰色小字，加了字距；拿掉字号以后，它还是灰色、还隔着字距，和条目标题分得开。

中文排版的细节，三份反倒都做得很好：汉字和英文、数字之间加了空格，「Wi-Fi」「2 GB」不让折行，引号和破折号交给了苹方。这些现在的模型已经会了，不用再写进规则。这篇讲它们没做到的三件事：层级为什么只靠字号分不开；文案来自接口时，空格该交给谁；用全角引号时，挨在一起的两个怎么办。最后给一段能列出任何页面字号表的脚本。

范围：三个全新的 Claude Code subagent 各写一次，2026-10-31；在 macOS 的 Chrome 156 里量（深色数据、空格和引号宽度是 2026-11-18 在 Chrome 157 里补测的），375px 宽的手机视口，没有在 Safari、Windows、Android 和真机上量过。prompt 和原始数据在附录。

## 档多不是问题

<TypeScale />

字号分几档不要紧，要紧的是页面上的上下两级靠什么分开。三份页面的文字各用了 6–7 种字号，13 到 18 之间几乎每个整数都用上了，看上去很乱；可 Apple 的 [iOS 默认字号表](https://developer.apple.com/design/human-interface-guidelines/typography)也有 10 档，17、16、15、13、12、11，相邻两档只差 1–2 个点。

这里要分清两件事：刻度上相邻的两档，和页面上的上下两级。iOS 的 Callout 16 和 Subhead 15 只差 1 个点，它们是刻度上的邻居，各管各的用处。iOS 字号表里同样大小的两档，靠的是别的通道：Headline 和 Body 都是 17 点，一个半粗、一个常规。刻度上挨得近不要紧，要紧的是上下两级之间，除了字号还有没有别的不同。

## 两级之间要有字号以外的不同

上下两级之间，要有字号以外的不同。开头的演示把所有文字改成同一个字号：还靠字重、颜色、字距分开的两级，仍然分得开；只靠字号的，就并成了一级。我们的解释是，字号的差别要放在一起比才看得出来，字重、颜色、字距是每段文字自己带着的，单独看一段也认得出属于哪一级；这个解释没有找到实验出处。留白和位置也要靠比较，所以下面说的「通道」只算字重、颜色、字距。

分组标题和条目标题偏偏很少紧挨着。「新功能」下面先是「断点续传」，再是一段说明，再是「链接有效期」。读者看到「链接有效期」时，要拿它和几行之上的「新功能」比，18 和 16 之间那 2px 比不出来，两级就看成了一级。三份页面在这一对上都只用了字号：

| | 分组标题 | 条目标题 |
| --- | --- | --- |
| 第 1 份 | 20px · 600 · 黑 | 16px · 600 · 黑 |
| 第 2 份 | 18px · 600 · 黑 | 16px · 600 · 黑 |
| 第 3 份 | 18px · 600 · 黑 | 16px · 600 · 黑 |

紧挨着的条目标题和说明反倒没问题：字号只差 1px，但一个是 600 的黑字，一个是 400 的灰字，很好分。第 1 份的 subagent 自查时注意到了分组标题不够突出，在汇报里写，把它从 18 改到 20，「so they stand out more from item titles」。改大有用，但还是只在字号这一个通道上；开头的演示切到第 1 份再拿掉字号，两级照样并成一级。

**怎么看出来。** 在 DevTools 的 Console 里运行下面这行，把所有文字改成同一个字号，再看页面上还剩几级：

```js
document.querySelectorAll('body *').forEach((el) => el.style.setProperty('font-size', '16px', 'important'))
```

拿掉字号以后并成一级的两种样式，如果在页面上是上下两级，就要再拉开一个通道。

**怎么写对。** 要么把分组标题放大到一眼就能看出差别，要么干脆换一种样式。我们试的是后一种，只在第 2 份的 `<head>` 末尾加了一段样式：

```css title="改过的版本加的样式（节选）"
.group-title {               /* 新功能、体验优化、问题修复；原来是 18px、600、黑 */
  font-size: 0.8125rem;      /* 13px */
  letter-spacing: 0.08em;
  color: var(--text-secondary);
}
.feature-title { font-size: 1.0625rem; }   /* 断点续传：16 → 17px */
```

改完以后，分组标题和条目标题在字号（13 和 17）、颜色（灰和黑）、字距三处同时不同，拿掉任何一处都还分得开。灰色小字的对比度，浅色模式 6.82:1，深色模式 8.54:1。没用主色，是不想让分组标题和链接长得一样。另外把条目标题和导语改成 17px、版本号 32px，文字的字号收成 13、15、17、32 四档。

**还有哪里会这样。** 凡是「一个标题管着下面好几项」的地方：表单里的分区标题和字段标签，卡片里的卡片标题和小节标题，设置页的分组标题和每一行的标题。它们之间都隔着别的内容，只靠字号拉开的，隔几行就认不出来。

## `pretty` 只治一个字的孤行

三份页面的段落都加了 `text-wrap: pretty`，它能做的比看上去少。我们把同样七段话，宽度从 300 到 430px 每 1px 排一次：最后一行只剩一个字的情况，`wrap` 下有 115 次，`pretty` 下是 0 次。但它只是把一个字变成两个字：最后一行只剩一两个字的总次数没变，都是 175 次，占 19.1%（[输出](/blog/lab/ai-typography/data/wrap.txt)）。[Chrome 的说明](https://developer.chrome.com/blog/css-text-wrap-pretty)也写着，`pretty` 目前「only handles orphans」。

所以加上它没坏处，但别指望它管住段尾。真正在意的短段落，比如提示框、按钮下的小字，要在最窄和最宽的视口下各看一次最后一行。

## 文案来自接口时，空格交给 CSS

空格写死在文案里，文案一换就没了；文案来自接口或运营后台时，空格要交给 CSS。三份页面的空格都是写进文案里的，这个静态页面没问题，接到接口上就不行了。

CSS 有专门做这件事的属性 [`text-autospace`](https://developer.mozilla.org/en-US/docs/Web/CSS/text-autospace)：在汉字和西文、数字之间自动加一点空白，不改文案。按 MDN，它 2025 年 11 月成为 Baseline，Chrome 140、Safari 18.4、Firefox 145 起支持。要注意的是，**浏览器默认不开。** [规范](https://drafts.csswg.org/css-text-4/)里它的初始值是 `normal`，会加；但 MDN 的兼容数据注明，三家浏览器目前的默认值都是 `no-autospace`（见 CSSWG 的 [issue #12386](https://github.com/w3c/csswg-drafts/issues/12386)）。三份 AI 页面都没有打开它。要用就自己写一行：

```css
body { text-autospace: normal; }   /* 浏览器默认是 no-autospace，不写就不加 */
```

<AutospaceLab />

它加的空白比手敲的空格窄：规范定的是 1/8 个汉字宽，手敲的空格落在英文系统字体上，正文字号下约 1/4 个字宽（[输出](/blog/lab/ai-typography/data/space-width.txt)）。W3C 的[中文排版需求](https://www.w3.org/TR/clreq/)（clreq）建议汉字和西文之间「up to 1/4 em」，两种都在范围里，看上去一个紧一点、一个松一点。

两者可以一起用。文案里已经有空格的地方，`text-autospace` 不会再加：我们量过，手敲空格再打开它，空隙和只敲空格时一样（[输出](/blog/lab/ai-typography/data/mixing.txt)）。所以稳妥的做法是 CSS 里打开 `text-autospace: normal`，接口来的文案照原样显示；手写的静态文案照常加空格。不支持的浏览器里，接口来的原文还是挨着的，至少内容没被改动。

## 全角引号挨在一起时，要自己挤

<PunctLab />

用全角引号，就要把「两个引号挨在一起」当成一种要处理的情况。先说背景：字体栈把英文系统字体放在前面时，引号和破折号会用上英文字体的字形：引号只有 0.44em 宽（15px 正文；字号越大越窄，40px 时 0.37em，[输出](/blog/lab/ai-typography/data/quote-width.txt)），细得像英寸符号；两个破折号并排时中间断开。三份 AI 页面都处理了，办法一样：用 `@font-face` 加 `unicode-range` 定义一个只覆盖这几个字符的字体，排在字体栈第一位，指向本机的苹方。这一条现在的模型也已经会了。

值得说的是第 3 份多走的一步：它打开了 `fwid`，取全角字形，每个引号占一个字宽，clreq 也写着标点「usually occupy 1 em」。全角引号的麻烦在挨在一起的时候。「“1 天”“7 天”」里，前一个的后引号和后一个的前引号各占一个字宽，中间空出将近一个字。

Chrome 默认的 [`text-spacing-trim`](https://developer.mozilla.org/en-US/docs/Web/CSS/text-spacing-trim) 会把相邻的全角标点挤紧，比如「）。」从 2em 挤成 1.5em。可对这种用 `fwid` 换出来的全角引号，它不起作用：挨着的两个仍然各是 1em（[输出](/blog/lab/ai-typography/data/quotes.txt)）。规范把弯引号列进了要挤的全角标点（「Also includes LEFT SINGLE QUOTATION MARK (U+2018) and LEFT DOUBLE QUOTATION MARK (U+201C).」），但也留了口子：字体没法区分全角和半角字形时，浏览器不能加减空隙。Chrome 判断引号是不是全角，看的是字体默认的字形；[Chromium 的源码注释](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/platform/fonts/shaping/han_kerning.cc)写着，用 `fwid` 切到全角字形是 Adobe 的约定，「The current logic doesn't support this convention」。第 3 份只好手动把前一个引号包进 `<span>`，换回英文系统字体的窄引号：

```html
<!-- 第 3 份的写法：挨着的前一个后引号换回英文系统字体的窄引号，.punct-tight { font-family: var(--font-text); }，字体栈以 -apple-system 开头 -->
分享链接可以选“1 天<span class="punct-tight">”</span>“7 天”或“永久”
```

所以选全角引号，就要把「挨在一起的引号」当成一种要处理的情况；选苹方的默认字形（0.54em），就不用操心。`local()` 只认本机装了的字体，各平台的字体名也不一样，换平台前要先量。

## 验收：列出页面的字号表

[间距篇](/blog/ai-spacing/)给了一段量间距的 X 光脚本，这篇给一段列字号表的。贴进 DevTools 的 Console 回车，右下角出现一个面板。

<TypeAuditRun />

它做三件事：

1. 列出页面上每一种文字样式，按字号排好，点一行就在页面上框出用它的文字。字号的计数包括提示框里的「!」图标，所以第 2、3 份和改过的版本会比正文里说的多一种。
2. 挑出「在页面上离得近、只差一个通道、而且差得不多」的样式对。离得近，指左右有重叠、上下间隔不超过两个字号；差得不多，指字号差 2px 以内、字重差 100 以内，或者两种颜色几乎一样。这几个阈值是经验值，不是哪份规范规定的。只看离得近的，是为了把比较限定在同一块内容里；分组标题和它下面紧贴着的第一条条目标题，正好落在这个范围里。
3. 查三件中文排版的事：`<html lang>`、`text-autospace` 开没开、正文字体排出来的引号是不是英文字体的窄引号。

在第 2、3 份上，它都只挑出 1 对：「新功能」和「断点续传」，只差字号 18 和 16。第 1 份的分组标题是 20px，差了 4px，超出阈值，没被挑出来，可它同样只靠字号区分。改过的版本上是 0 对。四份页面都没开 `text-autospace`（[输出](/blog/lab/ai-typography/data/snippet-output.txt)）。脚本挑出来的要逐个看；第 1 份这种差得多一点的，还要靠上一节那行「拿掉字号」。

## 给 AI 的规则

规则只补 AI 实测里漏掉的：

```md title="写进 AGENTS.md 或 skill 的排版规则"
- 页面上的上下两级（分组标题和条目标题、标题和说明），除了字号，至少还要在字重、颜色、字距里的一项上不同。
  交付前把所有文字改成同一个字号看一遍，并成一级的上下两级要再拉开一项；
  也可以在页面上跑一遍 /blog/lab/ai-typography/type-snippet.js，把它挑出的「容易看成同一级」的样式对逐个说明。
- 来自接口或后台的文案，不指望里面有空格：CSS 里写 `text-autospace: normal`（浏览器默认不开）。
```

## 附录：实测材料
