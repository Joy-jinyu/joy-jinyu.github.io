[Saltline](https://github.com/realcodebear/saltline-fable-5.2) 是一个浏览器里的第一人称射击游戏：雨夜的集装箱码头，切断三个上行中继站，同时躲开无人机（Gull）和机器狗（Hound）。它的特别之处在于**没有一个外部美术资源**。整个游戏只有一个 `index.html`（约 1.4 MB），里面打包了 three.js，模型、贴图、音效全部由代码现场生成。

据仓库 README 转述，这个游戏由 Claude Fable 5.2 在一次提示、没有人工反馈的情况下做出来，跑了约 8 小时，约 2.7M 输出 token、445M 输入 token，按 API 价格约 550 美元。这些数字来自原作者的帖子，仓库没有核实，我也没有核实。

我关心的是另一个问题：**没有建模软件、没有人看，它的 3D 模型是怎么做出来的？** 这篇是我读完代码后的整理。[在线演示](https://realcodebear.github.io/saltline-fable-5.2/)可以直接玩。

<Callout title="先说明读的是什么">
  仓库里的 `index.html` 是打包压缩后的代码，函数名被混淆成了 `$e`、`jn` 这样的短名字。好在着色器字符串里的注释、数据表的键名都保留了下来，足够还原思路。下文提到的函数名都是压缩后的名字；标了「示意」的代码是我整理过的写法，没标的是从源码里摘的原文。我读的方式是把 `<script>` 里的内容抽出来，用 prettier 格式化成约 7 万行再看，其中前 3.5 万行左右是 three.js 本身。
</Callout>

## 整体思路：模型是「写」出来的

每个物体都是一个 JavaScript 函数：用盒子、圆柱、管道和截面放样拼出形状，再套上 GPU 生成的 PBR 材质。支撑这件事的有五条原则：

1. **真实尺寸优先**。每种道具先在一张表里登记真实长宽高（米）和默认材质，再按真实工业规格补细节。
2. **工具层 + 构建器**。底层是十几个通用几何函数；上层每个物体一个构建器函数，按名字注册，可以单独重写。
3. **材质和形状分开**。几何体的 UV 按米展开，材质表写明一块贴图对应多少米，所以任何模型配任何材质，纹理密度都对。
4. **确定性随机**。凹痕、锈迹、箱号这类变化都来自带种子的伪随机数（全局默认 seed 是 4207），同样的参数永远得到同样的模型，前后截图才能对比。
5. **每个模块自带展示台**。渲染、材质、道具、关卡、远景、地面、特效、武器、敌人九个模块都导出 `create` 和 `showcase` 两个入口，后者可以把模块单独摆出来看。

前四条是建模方法，第五条是它能在没人看的情况下迭代的原因，放在[最后一节](#没人看的时候怎么知道模型对不对)讲。

## 几何原语：带「米制 UV」的基础形体

整个项目的建模只依赖十几个小函数。它们都在 three.js 自带几何体的基础上做了同一件事：**把 UV 改写成世界坐标（米）**，而不是默认的 0 到 1。

| 函数 | 做什么 | 关键处理 |
| --- | --- | --- |
| `$e` | 长方体 | 按法线主轴做盒投影，UV 直接取顶点坐标；可选底部对齐 |
| `Wi` | 倒角长方体 | 3×3×3 细分后把棱角顶点推到圆角上，并修正法线，做出倒角高光 |
| `ot` | 圆柱 | 侧面 U 乘以周长，端面用 XZ 坐标 |
| `Fn` | 管道、线缆 | 沿 Catmull-Rom 曲线生成 TubeGeometry，分段数按长度自动算 |
| `la` | 截面放样 | 二维轮廓沿一组位置拉伸，可以用回调逐顶点变形 |
| `Lc` | 顶点色 | 用常量或 `(x, y, z) => rgb` 函数给顶点上色 |

长方体的 UV 改写只有几行（源码原文，变量名是压缩后的）：

```js
function $e(i, e, t, n = "center") {
  let s = new un(i, e, t), // un 就是 BoxGeometry
    o = s.attributes.uv, r = s.attributes.position, a = s.attributes.normal;
  for (let l = 0; l < o.count; l++) {
    let c = Math.abs(a.getX(l)), u = Math.abs(a.getY(l)),
      h = r.getX(l), f = r.getY(l), p = r.getZ(l);
    // 朝 X 的面用 (z, y)，朝 Y 的面用 (x, z)，其余用 (x, y)
    c > 0.5 ? o.setXY(l, p, f) : u > 0.5 ? o.setXY(l, h, p) : o.setXY(l, h, f);
  }
  return n === "bottom" && s.translate(0, e / 2, 0), s;
}
```

这样做的好处是：6 米长的集装箱和 0.3 米的小箱子用同一个「波纹钢板」材质，波纹间距一致，不会被拉伸，也不用给每个模型手调 UV。

## MeshBuilder：变换栈、按材质分桶、合并

道具和大型结构都通过一个构建器类（压缩名 `jn`）来拼。它提供 `box`、`cyl`、`tube`、`bar`、`beam`、`decal` 等方法，内部做三件事：

- **变换栈**：`push(matrix)` / `pop()`，像老式 OpenGL 那样一层层嵌套坐标系，拼重复部件很方便。
- **按材质分桶**：每加一块几何体，就放进对应材质的桶里，可以同时写入顶点色。
- **合并输出**：`group()` 把每个桶合并成一个 Mesh。一台由上百个零件组成的叉车，最后只剩「每种材质一个 draw call」。

一个道具构建器大致长这样（示意）：

```js
function buildBollard(G, opts = {}) {
  const b = new MeshBuilder(G)
  const rnd = seeded(opts.seed | 0)        // 确定性随机
  const iron = b.M('steel_dark')           // 按名字取材质
  b.cyl(iron, 0.28, 0.32, 0.5, 0, 0.25, 0, { seg: 16 })
  b.cyl(iron, 0.35, 0.35, 0.06, 0, 0.53, 0)
  b.tube(b.M('rope'), [[0.3, 0.4, 0], [0.8, 0.2, 0.4], [1.5, 0.1, 0.2]], 0.02)
  // 返回模型，同时带上尺寸和碰撞盒
  return named(b.group(), 'bollard_mooring', [0.7, 0.6, 0.7], [
    { min: [-0.35, 0, -0.35], max: [0.35, 0.6, 0.35], surface: 'metal' },
  ])
}
```

返回的不只是模型，还有 `userData.size`（包围尺寸）和 `userData.colliders`（几个轴对齐碰撞盒，加上表面类型，用于物理和脚步声）。模型、碰撞、音效分类在同一个函数里一次定义，不会出现模型改了、碰撞盒忘了改的情况。

## 照着真实工业规格建模

道具模块里有一张 `PROP_SIZES` 表，列出 36 种道具的真实尺寸和默认材质，摘几行：

| 道具 | 长 × 高 × 宽（m） | 默认材质 |
| --- | --- | --- |
| `container40hc`（40 尺高柜） | 12.19 × 2.90 × 2.44 | paint_green |
| `container20`（20 尺柜） | 6.06 × 2.59 × 2.44 | paint_red |
| `forklift`（叉车） | 3.40 × 2.20 × 1.25 | paint_yellow |
| `jersey_barrier`（混凝土防撞墙） | 3.00 × 0.81 × 0.60 | concrete |
| `pallet`（托盘） | 1.20 × 0.144 × 1.00 | wood_pallet |

这张表也是**兜底方案**：某个道具没有专门的构建器，或者构建器抛了异常，就按表里的尺寸生成一个带材质的方块和碰撞盒，关卡照样能玩。

集装箱最能体现这种「考据」：

- 箱宽取 ISO 标准的 2.438 m；
- 标签用真实的 ISO 6346 箱型代码（22G1、42G1、45G1），写上总重、皮重、净重和容积；
- 箱号是「4 位字母 + 6 位数字 + 校验位」的格式，例如 `SLTU 482915 7`；
- 波纹板有单独的截面参数，节距 0.278 m、深 0.036 m；
- 箱体上的凹痕由种子随机生成，并且会主动避开箱门和标签区域。

混凝土防撞墙则用到了**截面放样**：12 个点描出真实的 F 型截面（底宽 0.6 m、高 0.81 m），沿 3 m 长度拉伸，两端的顶点在回调里略微收窄，做出浇筑件的倒角。然后加上叉车插槽、两个生锈的吊环，碰撞体拆成「宽底座 + 窄上部」两个盒子。

## 用顶点色做旧，而不是画贴图

每一块防撞墙看起来都不一样，靠的不是不同的贴图，而是顶点色。防撞墙的顶点色回调里叠了好几层规则：

1. 两级噪声做基础明暗；
2. 离地 0.3 m 以内变暗（油污、泼水）；
3. 噪声控制的水渍；
4. 某个高度带上的黑色擦痕；
5. 7 个随机位置的磕碰亮斑；
6. 两端边缘发白。

顶点色和平铺的材质相乘，成本几乎为零。

## 材质：在 GPU 上烘焙 PBR 贴图

材质是这个项目里最重的部分。它没用 Canvas 2D 画贴图，而是在启动时用全屏片元着色器把每种材质渲染到纹理里。

**材质表**（压缩名 `c3`）定义了 29 种基础表面：沥青、混凝土、砖、波纹板、镀锌钢、锈、花纹钢板、铁丝网、碳纤维、帆布等。每一项写明分辨率系数、一块贴图对应的米数（波纹板是 0.762 × 2.286 m）和凹凸强度。`paint_red`、`paint_blue` 这类带颜色的变体在此基础上参数化。

**一次输出三张图**。着色器用 WebGL2 的多渲染目标（MRT）同时写出三张图，下面是源码原文：

```glsl
void emit(vec3 c, float a, float h, float ao, float r, float m){
  o0 = vec4(sqrt(clamp(c, 0.0, 1.0)), sat(a));          // 反照率 + 透明度
  o1 = vec4(sat(ao), clamp(r, 0.03, 1.0), sat(m), 1.0); // AO / 粗糙度 / 金属度
  float hh = sat(h) * 255.0; float fl = floor(hh);
  o2 = vec4(fl / 255.0, hh - fl, 0.0, 1.0);             // 高度拆成两个 8 位通道，凑成 16 位
}
```

再由第二个着色器对高度图求差分，得到法线贴图。

**无缝平铺**。所有噪声函数（梯度噪声、fbm、Voronoi、划痕）都带一个周期参数，取哈希前先对格子坐标取模，贴图边缘天然能接上：

```glsl
vec3 h3(vec2 c, vec2 per, float s){
  c = mod(c, per);  // 按周期取模，左边缘和右边缘拿到同一个随机数
  return vec3(pcg3(uvec3(uint(c.x + 0.5), uint(c.y + 0.5), uint(s + uSeed)))) * (1.0 / 4294967296.0);
}
```

**共享的漆面损伤模型** `paintDmg`：先用低频噪声划出「损伤集中区」（源码注释原话是 *most of the panel is clean*，大部分面板是干净的），再叠两级纵向拉长的掉漆、两组方向不同的划痕，最后把掉漆的位置向下错开采样 4 次，生成锈水流痕。所有涂漆类材质都用这一套，所以整个码头的「旧」是统一的。

**运行时改写标准材质**。生成的贴图交给 three.js 的 `MeshStandardMaterial`，再通过 `onBeforeCompile` 替换 `map`、`roughness`、`metalness`、`normal`、`ao` 这几段着色器代码，注入一个全局的「湿度」uniform，让所有表面在雨里一起变暗、变光滑。

## 敌人：代码里定义骨骼，IK 驱动腿

敌人也没有导入的模型和动画。一个小 rig 类用 `bone(name, parent, x, y, z)` 逐个声明骨骼：

- 机器狗：root → body → neck → head，加上炮塔、枪、天线、信标，以及四条腿各自的髋、大腿、小腿；
- 无人机：4 个旋翼骨骼。

每个零件刚性绑在一根骨头上（skinIndex 只有一个，权重为 1），整只敌人合并成一个 SkinnedMesh。腿用余弦定理做双骨 IK，步态和悬停晃动是带随机相位的正弦波叠出来的。

## 武器：不展 UV 的近景细节

第一人称武器 PAC-9 离镜头只有几十厘米，对细节要求最高。它给阳极氧化金属、磷化层、哑光件、聚合物各建一个材质，在着色器里把物体空间的坐标和法线传到片元阶段，直接在片元里算粗糙度和法线扰动。这样小零件不用展 UV，也没有接缝。持枪、瞄准、换弹的姿态是代码里写死的 `{ p, r }` 常量，用弹簧阻尼函数插值。

## 远景与性能：同一个构建器，两种精度

岸桥起重机这种大结构，构建器有一个 `into` 模式：同一套建模代码，把灰、黄、白、红漆和镀锌钢这些材质重新映射成「单一材质 + 顶点色」，并丢掉尺寸小于 2.6 m 的零件，生成一个便宜的远景版本。

其他几处优化：

- 场景级再按「材质 + 阴影设置」合并一次，不想被合并的物体打上 `noMerge` 标记；
- 启动时读取 GPU 型号字符串，把移动端、软件渲染和集显归到低档或中档，贴图分辨率和阴影尺寸跟着调。

## 没人看的时候，怎么知道模型对不对

代码里留着一整套可以被脚本驱动的接口。结合「无人工反馈、跑了 8 小时」的背景，我推断它的生成过程是一个「写构建器 → 单独渲染 → 截图检查 → 修改」的循环。下表是代码里能直接看到的机制，用途一栏里写「推断」的是我的猜测：

| URL 参数 / 全局变量 | 作用 |
| --- | --- |
| `?show=<模块>` | 不加载关卡，只在一块 80 m 的混凝土地面上调用该模块的 `showcase()`。例如 `?show=props` 把所有道具按每行 26 m 排开 |
| `&names=a,b` | 只展示指定的几个道具 |
| `&cam=x,y,z,tx,ty,tz`、`&fov`、`&exposure` | 精确指定机位和曝光，前后两张截图可以对比 |
| `&seed`、`&tex`、`&wet`、`&q` | 固定随机种子、贴图分辨率、湿度和画质档位 |
| `&shot`、`#bench` | `shot` 切到 test 画质档；`bench` 关掉音频并自动开始（推断：用于自动截图和性能测试） |
| `window.__ready`、`__frames` | 是否启动完成、已渲染几帧，外部脚本据此判断什么时候可以截图 |
| `window.__errors`、`__fatal` | 所有 `console.error` 和未捕获的异常都收集到这里 |
| `window.__setShot()`、`window.__G` | 运行中切换机位；访问全局游戏状态 |

启动流程对每个模块都做了容错：模块的 `create()` 抛异常时，除了渲染、关卡这类必需模块，都会退回一个简化的占位实现；单个道具构建器出错时退回尺寸表里的方块；耗时超过 150 ms 的模块会打日志。长时间迭代时，一个模型写坏了不会拖垮整个游戏，错误信息又能被脚本读到。

把这些拼起来，一个模型的生产过程大致是：

1. 在尺寸表里登记真实尺寸和默认材质。这时已经有一个能用的方块占位。
2. 写构建器：用几何原语拼大形，再叠细节、顶点色和碰撞盒，按名字注册。
3. 用 `?show=props&names=<名字>&cam=...` 单独渲染并截图，检查 `__errors`。
4. 对照截图修改，回到第 3 步；没问题了再摆进关卡。

## 能带走的做法，和它的局限

可以直接拿来用的做法：

- **先写数据表，再写模型**。把「模型长什么样」拆成「多大、什么材质」和「细节」两步，前者马上能用，后者慢慢补。
- **米制 UV + 按物理尺寸平铺的材质**。程序化建模里性价比最高的一条规则，省掉所有手工展 UV 的活。
- **构建器统一返回「模型 + 尺寸 + 碰撞体 + 表面类型」**，模型和物理不会各写一份、对不上。
- **按材质合并**。拼的时候可以用很多小零件，输出时还是少量 draw call。
- **确定性种子 + 可参数化的展示台 + 可读的错误池**。这是让 AI（或 CI）看到自己产出的前提，人类团队拿来做视觉回归测试也合适。
- **统一的损伤和天气模型**。掉漆、锈流、湿度做成共享函数和全局 uniform，所有物体的「旧」和「湿」自然一致。

局限：

- **代码量大，可读性差**。一个防撞墙就是上百行魔法数字，发布版又是压缩代码，人接手改的成本很高。
- **适合硬表面工业物体，不适合有机形体**。集装箱、起重机、机器人都是盒子和管子拼的，正好是这套方法最擅长的；人物、动物、植物很难这么做好。选「码头 + 机器敌人」这个题材，本身就是在放大这套方法的优势。
- **每次加载都要重新生成**。所有贴图和几何体在启动时现算，换来的是极小的文件体积，以及不依赖任何外部资源。
- **成本不低**。按 README 转述的数字，一次运行约 550 美元、8 小时，大量 token 花在反复截图、修改上。换成人来写同样的构建器，工作量同样不小。
