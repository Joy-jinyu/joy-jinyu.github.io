# UI 规则

只写 AI 实测里漏掉、或者这一批做对了但不稳定的事，每条都写成能检查的动作。出处是 UI 审美系列各篇的附录；
脚本路径相对博客根目录（https://www.pairwise.site）。

## 布局

- 两块看起来该对齐的元素，用同一个公式算宽度，留白也算在里面：
  例如两块都写 width: min(var(--col-w), 100% - 2 * var(--gutter))，外层不再加左右留白。
  只共用一个 max-width 变量还不够：一个把留白写进自己的 padding、一个写在外层，照样对不齐。
  改完把窗口从最宽拖到最窄，确认边始终重合。
- 只让局部区域滚动时，滚动的那一层和要跟它对齐的每一层都加 scrollbar-gutter: stable；
  用常显滚动条检查一遍两者的中线。
- 新内容到达时，只有用户离底部不到 120px 才自动滚到底，这个距离在插入内容之前算；
  用户自己刚发的消息可以直接滚到底。
- 藏起来的内容要同时藏掉点击、焦点和读屏：transform、opacity、height: 0 都不够，
  收起时用 visibility: hidden 或 inert。
  带遮罩的抽屉按 WAI-ARIA APG 的模态对话框来做：打开时焦点移进去，
  后面的页面设为 inert，Esc 关闭后焦点回到打开它的按钮。
- 改完跑 node layout-check.mjs <页面>（脚本在 /blog/lab/ai-chat-layout/layout-check.mjs，先下载到本地），全部通过再交付。

## 动效

- 同一个动画要走不同距离时（折叠面板的长短答案、大小不一的弹层），
  时长按距离算，不要共用一个固定值：例如 clamp(200ms, 160ms + 0.5ms × 高度, 450ms)。
  曲线最陡处的斜率不超过 2，例如 cubic-bezier(0.5, 1, 0.89, 1)；
  减速曲线最陡处在起点，斜率是 y1 ÷ x1；起点平缓的曲线要看整条（cubic-bezier(0.2, 0, 0, 1) 中段是 4.05）。
  估算：每帧最大位移 ≈ 最陡处斜率 × 距离 × 16.7 ÷ 时长，控制在 60px 以内。
- 动画结束后的收尾（移除节点、设 hidden）等 transitionend 或 animation.finished，
  定时器只做兜底；不要在 JS 里再写一个和 CSS 差不多长的时长。

## 间距

- 文字相关的间距按「看到的」定：从字形的上下边量，不从行盒量。
- 单行的标题、标签、说明，用 `text-box: trim-both cap alphabetic` 裁掉上下的空白，
  再用 `padding-block: 0.16em 0.12em` 把汉字冒出去的部分补回来，整段包在
  `@supports (text-box: trim-both cap alphabetic)` 里。字体栈不是「英文系统字体在前」时，先量再定这两个值。
- 同一组里看到的间距，不超过组与组之间的一半。
- 交付前在页面上跑一遍间距 X 光（/blog/lab/ai-spacing/xray-snippet.js），列出每组「写的 / 看到的」间距。

## 排版

- 页面上的上下两级（分组标题和条目标题、标题和说明），除了字号，至少还要在字重、颜色、字距里的一项上不同。
  交付前把所有文字改成同一个字号看一遍，并成一级的上下两级要再拉开一项；
  也可以在页面上跑一遍 /blog/lab/ai-typography/type-snippet.js，把它挑出的「容易看成同一级」的样式对逐个说明。
- 来自接口或后台的文案，不指望里面有空格：CSS 里写 `text-autospace: normal`（浏览器默认不开）。

## 风格

- 新页面先确定风格来源：引入团队的变量文件（首选），或者指定一张参考页。只写「和现有风格一致」不算来源。
- 变量文件里没有的项（字重、控件高度、悬停和按下的颜色），可以先定一个值，但只在页面开头一个集中的 `:root` 块里
  定义成变量，全页只引用它；缺深色值就不做深色，不要自己编一套。交付说明里列出缺了哪几项、用在哪里，请人补进变量文件。
- 照着参考页写时，参考页里对比度不到 4.5:1 的配色，不要用到新元素上：改用变量表里合格的一对，并在交付说明里写明。
- 交付前在页面上跑一遍 /blog/lab/ai-consistency/style-snippet.js，把「变量之外」的每一处列出来，说明为什么不用变量。

## 状态

- 每个请求都要设超时（fetch 没有默认超时），例如 `AbortSignal.timeout(15000)`；超时按失败处理：
  给出能看懂的提示和重试入口，把按钮上的「……中」和禁用状态恢复过来。
- 一个操作会让当前聚焦的元素消失或被藏起来时（重试、删除、关闭），先把焦点移到下一个合理的位置，再移除元素。
- 交付前在浏览器里自测，接口模拟脚本是 net-snippet.js（/blog/lab/ai-states/net-snippet.js，先下载到本地）。
  用 Playwright 的 `addInitScript` 只注入一段，内容依次是 `window.__netLabHeadless = true;`（不画面板）和脚本全文；
  多段 init 脚本的执行顺序没有保证，不要拆开注入。分两次测：
  首次加载：在这一段末尾再加 `window.__netLab.set('hang');`，打开页面，等过超时，确认加载状态结束了（reload 后又会是 hang）；
  按钮：不加这一句，等页面正常加载完，再用 `page.evaluate(() => window.__netLab.set('hang'))` 切过去，
  把每个会发请求的按钮点一遍，等过超时，确认每个「……中」都结束了；
  再只用键盘把会自己消失的按钮按一遍，确认焦点没有落回 body。

## H5

- 写了 `viewport-fit=cover`，四条边都要处理：贴边的栏和正文同时补上左右的安全区边距，
  写成 `padding-left: max(原来的值, env(safe-area-inset-left))`，右边同理；不能只处理上下。
- 交付前的浏览器自查要模拟安全区边距（CDP 的 Emulation.setSafeAreaInsetsOverride），
  竖屏 393×852（上 59、下 34）和横屏 852×393（左右 59、下 21）各查一遍：可点元素不能伸进边距；
  栏高的预算按安全区以内的高度算，横屏也要算；横屏超了，先让顶栏不吸顶（`position: static`）。
